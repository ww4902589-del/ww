# S / ComfyBatch V2.21 交接：SQLite 本地作品库

## 本次交付

任务清单第 4 项。新增本地作品库：把每个批次里的每一张成图变成**一条可跨批次检索的记录**。

- 新增 `src/comfybatch_library.py`：单文件 SQLite（`<数据目录>/library.db`），
  `works` / `work_tags` / `runs` 三张表，`schema_version = 1`。
- **作品库是派生索引，不是第二个真相源。** 派生列（标题、提示词、种子、模型、路径、
  尺寸、字节数、确认状态…）每次同步都从复核文档重写；用户列（收藏、标签、删除标记）
  由 `_SYNCED_COLUMNS` 白名单在 SQL 层强制不许被同步覆盖。
- 逐条对应关系：`work_id = "<run_id>:<编号四位>"`，**不是文件路径**——重做会换掉文件，
  标签与收藏必须留在同一条记录上；`indexed_at` 只在插入时写。
- **删除是墓碑不是删行**：`deleted_at` 落行，重新索引不会复活已移除的记录，
  可「显示已移除」恢复，且**从不触碰磁盘上的成图**。
- 检索：关键词（标题/提示词/负面词/备注/模型/种子/编号/标签）、批次、确认状态、
  标签、只看收藏、显示已移除、五种排序、分页与总数、`facets`（状态、标签、批次）。
- 端点：`GET /api/library`、`GET /api/library/preview`、`GET /api/library/image`、
  `POST /api/library/{favorite,tags,delete,restore,reindex,maintain}`；
  写路由全部进 `WRITE_ROUTES`，受既有编辑租约保护。
- 读图边界：预览与原图**只接受 `work_id`**（预览多一个 `size`），路径由服务端从库里取；
  白名单之外的参数一律 400，取到的文件还要过"是图片扩展名"与"真能被解码"两道闸。
- 页面：新增第 5 阶段「作品库」（`data-step="5"`／`LAST_STEP` 4→5），进入才惰性读取；
  筛选条 + 卡片网格（缩略图点开原图、模型/种子/尺寸/字节数/尝试次数、标签行、收藏、移除）+ 分页。
- 文档：`docs/21-SQLite作品库_V2.21.md`。

`APP_VERSION` 保持 `2.20`：仓库里版本号只在发布提交里提升（`8b8361b` 就是这么做的），
本分支是交接分支，不替发布提交做这件事。

## 真机上撞到并修掉的三个真问题

**一、默认排序把"成图已不在原位"的记录排在前面。**
第一版 `newest`/`oldest` 的排序键是 `COALESCE(mtime_ns, indexed_at*1e9)`。
看起来等价，实际是错的：全失败的批次没有文件，于是每条都拿到"刚刚入库"的时间戳，
集体冒到用户真正拥有的作品之上。用真实复核文档回填时，`?limit=50` 前 50 条
**一条可用成图都没有**，直接暴露。改为按**图片自己的 mtime**排序、没有文件的记录排在
后面，并加回归测试钉住。

**二、作品库打不开会让整个程序打不开。**
`Application` 在模块级构造 `LibraryStore`，而 `_prepare()` 只兜住了第一次失败：
损坏文件挪不走时，第二次建表会把 `sqlite3.DatabaseError` 抛出构造器。
为了一个可重建的索引付"程序打不开"的代价是错的。现在两次失败都降级：库标记不可用、
原因写进 `last_warning`，路由返回 **503**（不是 400——"库不可用"不该伪装成"你请求错了"），
审图页照常工作。

**三、排序下拉里显示的是 SQL 片段。**
`SORTS`（SQL 排序子句）被直接当成选项文本发给页面，下拉框里写着
`(mtime_ns > 0) DESC, mtime_ns DESC, ...`。现在由 `SORT_LABELS` 提供
「最新／最早／按批次编号／按种子／按文件大小」，页面显示标签、取值仍是排序键。

## 自查发现并修掉的第四个问题

**"打开失败"曾被一律当成"文件损坏"。**
损坏库的恢复逻辑是"把坏文件另存一份、新建一个空库"。但打开失败的原因不只有损坏：
另一进程短暂占锁、一次瞬时 I/O 错误、"能读不能写"都会让打开失败。这种情况下把一份
**完好的**库挪走，等于让用户丢掉全部标签与收藏——代价远高于"这次不可用，下次再试"。
现在只有文件开头**没有**那 16 个字节的 SQLite 文件头（`SQLite format 3` 加一个终止字节）才判定为损坏并另存；
看着仍是数据库的，标记不可用、保留原文件、不改一个字节。
