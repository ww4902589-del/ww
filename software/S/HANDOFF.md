## 本次交付

- **把"实际种子"读回来。** 之前页面上的 `seeds` 只是**提交值**——我们请求 ComfyUI 用的
  数字，不是这张图真正用的数字。现在从成图 PNG 内嵌的 `prompt` 文本块（ComfyUI 写入的
  **实际执行**图）读出真实种子，读不到才退回 `/history/<id>` 的执行图。
- **引入第三种状态「未核对」。** 两处都读不到时 `effective` 是 `None` 而不是 `False`，
  卡片写「种子（未核对）」。读不到 ≠ 没生效；把两者混同，会让每一张旧图、每一个被改过
  元数据的文件背上一个假罪名。
- **卡片显示实际种子并标明来源**（`← 图片内嵌提示` / `← 执行历史`）。提交值与实际值不一致
  时两者都列出并标出差异，「复用」按钮填的是**实际**种子——"复现这一张"复现的是它真正的样子。
- **预检阶段就说明种子能不能被固定。** 把全图种子分成 `pinnable` / `linked` / `uncontrollable`
  三类。当种子由**没有可写种子参数的上游节点**提供时，固定种子对这张图完全无效——这是
  真实存在的形状，而旧实现只在"提交值恰好等于上次"时才提示「固定种子未生效」，随机工作流
  永远不相等，所以**永远不会提示**。现在预检直接给出直白告警，真相栏也新增「种子」一行。
- **批次报告新增** `real_values`、`real_duplicates`、`mismatched`、`unverified_indexes`，
  回答"哪几张其实是同一张""哪几张的种子被改过""哪几张没核对上"。
- 判断上游"能不能被固定"时看**全图**（含静音分支），因为生产工作流常把种子节点放在静音
  分支里；只看当前分支会把可固定的工作流误报成"不可控"。
- 同步更新 `docs/04-资源替换与种子.md`（新增实际种子证据链、三态语义、种子计划三分类）。

## 真实生图验收（真实 ComfyUI + 真实 Krea2/SeedVR2 工作流）

固定种子跑三批，用**像素**而不是文字回答"种子到底有没有生效"：

```
批 1  固定 424242  提交/实际/图片内嵌 = 424242  生效=True  像素 42b3556c938b275e
批 2  同 424242    提交/实际/图片内嵌 = 424242  生效=True  像素 42b3556c938b275e   ← 逐像素相同
批 3  固定 999999  提交/实际/图片内嵌 = 999999  生效=True  像素 c77af964e4d1b3f1   ← 不同
```

- 同一固定种子重跑 → 像素**相同**；换固定种子 → 像素**不同**。**验收：通过。**
- **三方一致**：提交值、报告实际值、成图内嵌值三批全部相等——证明读取路径真的读到了图，
  而不是把提交值原样抄一遍。
- 该工作流是 `linked` 型：`20.seed` 可固定，`21.noise_seed` 与 `13.seed` 由它飞线驱动，
  所以写一个节点就定住两个采样器，种子偏移保证两者不会撞成同一个值。
