本目录是基于《S-研发计划与调整记录》与《S-研发资料包-2026-09-14-v1》对软件 **S**

而程序版本 `APP_VERSION` 已更新到 **V2.20**（页面标题与 `/api/ping` 都由它驱动，
测试 `test_server_and_page_versions_agree` 盯着两者一致）。
V2.20 候选包保留在 `build\dist-v220-release\S.exe`。**桌面运行的 `S.exe` 已更新为含
本地作品库的候选**（第 17 条，2026-09-24 部署；`APP_VERSION` 按 V2.21 文档的决定
保持 2.20 不动）：源码取自 PR #8 合并提交 `9c309ef`，SHA-256
`4515FF0EFB992CE30D5E64D32B090537E17590FF310C720D9845AC14EA8C85D2`；
被替换的 V2.20 版备份为桌面 `S.exe.v220-backup-20260924`。
旧版回退件保留在 `run\backups\`（09-14 胖版与 09-15 版各一份）。

## 本轮做了什么

计划书的 P0+P1 是“错误可见与批次止损”与“参数与资源预检”。落实到代码时发现，
阻断新极清工作流的根因比计划书描述的更严重，因此本轮以**替换工作流编译层**为核心：

1. **模式驱动编译器**（按名字绑定控件值），替换了 V2.13 的“按位置猜参数”。
   位置游标在原理上不可能正确——详见 [根因分析](docs/01-根因分析.md)。
2. **保留并翻译 ComfyUI 错误正文**，按 ComfyUI 自带的错误类型串分类成 10 类中文错误，
   并给出可执行修复步骤与本机候选值。
3. **批次止损**：工作流级错误首条即停；连续失败熔断；执行失败由秒级判定取代 1800 秒空转。
4. **四层预检**：结构 → 资源 → 参数 → **最终提交图审计**（含逐输入溯源）。
5. **成图预览与打回重做**：页内看板、逐张确认/打回/记录问题、四种重做方式、
   键盘审图、重启后确认状态与结果恢复。
6. **错误抽屉**：V2.13 完全不渲染 `results[].error`，现在可点击查看中文原因与原始报文。
7. **软件内替换缺失资源**：预检报缺的资源可直接在抽屉里选本机候选替换，支持「仅本次批次」
   与「保存为永久规则」两种作用域，并可一键打开对应模型目录。**不做静默替换**——替换值在
   审计里标记为「用户在软件内替换」，随时可删。
8. **种子可见可控**：每张图卡片显示它真实的提交种子；批次可固定种子；重做可指定种子。
9. **替换规则不会悄悄失效**：指纹用**结构性指纹**（拖动画布上的节点不会让规则失效）；
   工作流真的改到结构变了，旧规则会被识别出来并提示，附一键「沿用旧替换规则」。
10. **参数工作台**：26 个参数（常用 10 + 高级 16）可在页面里改，四种作用范围
    （整个批次 / 工作流默认值 / 仅选中任务 / 沿用工作流），并区分一采与二采；
    「整个批次」下可勾选**记住这次的参数**，勾上后这一批的值同时存为该工作流默认值。
    一份声明同时驱动界面、校验与写入，所以页面显示的值就是提交给 ComfyUI 的值。
11. **单实例**：第二次启动不再新开后端，而是激活已有实例并把页面切到当前任务
    （Windows 命名互斥体 + `instance.json` + `/api/activate`，并核对 instance_id 以免认错目标）。
12. **事件流与编辑租约**：SSE 替代轮询，多页面实时同步；同一时刻只有一个页面可编辑，
    其余只读并可主动「接管编辑」。关掉的标签页会在 45 秒后自动释放租约，不会锁死界面。
13. **删除不会被复活**：预设删除写入墓碑，墓碑集合是所有副本的并集；实体只来自单一权威
    文件，不再跨文件并集。安装目录那份旧副本改为**只读迁移来源**，更新替换它不可能
    重新引入旧数据。只有点「恢复出厂预设」才会重建，且只重建出厂模板里有的。
14. **导入模块完全只读**：加载没有副作用，迁移只在内存生效，由下一次真正的保存落盘。
15. **前端重新规划**：单文件页面拆成 `index.html` / `app.css` / `app.js`，按计划书重排为
    分阶段流程（当时的四个阶段是文件与任务 / 生成配置 / 检查与运行 / 成图与确认；
    第 5 阶段「作品库」见第 17 条），
    右侧加**常驻真相栏**（工作流、指纹、分支、模型、尺寸、参数、阻断、结果、进度），
    渲染收敛为一个入口。重排过程中修掉 6 个缺陷——含"同一屏上两个不同的工作流指纹"、
    "阻断时真相栏自称没有阻断问题"、"左侧导航压住内容使按钮点不到"。
    详见 [前端重新规划](docs/08-前端重新规划.md)。
16. **链接图片提取**：可导入公开网页、图片直链与 B 站视频封面；提取器独立处理地址安全校验、
    重定向、图片验证与来源信息，导入仍复用原有图片任务链路。详见
    [V2.20 记录](docs/17-链接图片提取_V2.20.md)。
17. **本地作品库**：新增第 5 阶段「作品库」，把每个批次里每一张成图变成一条可跨批次检索的
    记录——按关键词、批次、确认状态、标签、收藏与五种排序找图，可收藏、打标签、
    从库中移除（只动记录，**不动磁盘上的成图**）。它是从复核文档派生的索引，
    不是第二个真相源。详见 [V2.21 记录](docs/21-SQLite作品库_V2.21.md)。

顺带修复的独立缺陷：负面提示词漏掉 `KSamplerAdvanced`、9 个内置图像规格中 5 个使用了
ComfyUI 不接受的比例标签、放大模型清单从未被枚举、换行落进 HTML 属性值使
`<select id="${sel}">` 与预期字符串不再相等、`body:'{}'` 被断成字符串跨行导致整段脚本静默死亡。

## 成图落盘与预览修复（本轮追加）

针对"图片的预览和存储也是个问题"单开的一轮，两个缺陷都用真实批次跑出来的，
详见 [成图落盘与预览修复](docs/09-成图落盘与预览修复.md)。

1. **成图存不下来**（`[WinError 3] 系统找不到指定的路径`）。ComfyUI 上报输出文件的两种
   形状对"目录归谁"说法不一致：一种 `subfolder="a/b"` + 裸文件名，另一种 `subfolder=""`
   + 文件名里已带 `a/b`。原代码无条件拼接，第二种形状下算出 `output/a/b/a/b/x.png`，
   文件当然不存在。更麻烦的是 `shutil.copy2` 抛的是普通 `OSError` 而非工作流级
   `Problem`，**止损逻辑看不见它**，于是每条任务失败一遍、批次照常走完，
   报一个看起来正常的 `completed_with_errors`。现在 `resolve_output_source()`
   按分段比对后取正确的那一份。
2. **输出目录不再重建 ComfyUI 内部目录树**，也不再自己复制自己（输出目录若在 ComfyUI 输出根内，
   原写法 `source == target` 会抛 `SameFileError`）；重名改为依次取 `-v2`、`-v3`
   而不是互相覆盖。三处重复的复制代码合并成 `copy_output_image()`。
   > **后续修订**：起初把文件名压平成裸名，但 `ComfyBatch-V2/<run>/` 里的 `<run>` 层级正是
   > 把一批图组织成集合的东西，压平后不同批次的同名图会撞名。现行行为是
   > **保留 `<run>/`、只丢掉 App 命名的 `ComfyBatch-V2` 那一层**，
   > 两种上报形状归一化后落点一致。详见 [§1.1](docs/15-待决问题修改方案预设.md)。
3. **预览不再拉全尺寸原图**。看板与画廊原本每个 `<img>` 都指 `/api/image`，
   20 张批次打开即数百 MB，且每次推送/轮询重渲染都重拉一遍；
   `thumbnail` 字段则一直是被硬编码的空字符串。现在新增 `/api/preview` 与
   按源文件哈希缓存的 512px 预览（存在应用数据目录，不随输出目录移动而丢失），
   查看器先开 1600px 预览、点图再切原图。实测数据量**下降 99.4%**
   （4×2048² PNG：48.08 MB → 274.8 KB）。
4. **打回重做不再手打英文枚举值**。原来弹两次 `prompt()`，让用户把
   `same_seed` 这类值原样敲进去，敲错只回一句"不支持的重做方式"。
   现在改为下拉选择 + 中文说明（选项由服务端 `redo_modes` 驱动），原因用多行输入框。
5. **查看器「看原图」切不回来**。`toggleViewerFull()` 靠 `activeIndex` 反查当前行，
   但那个变量只有 `setActive()` 会写；从画廊网格或结果卡点开大图时它还是 `-1`，
   于是第二次点图会切到一个空 `path=` 的预览、图片裂掉。改成查看器自己记住
   展示的是哪一张（`viewerIndex`），入口之间不再互相依赖。
6. **明明装着模型却说不兼容**。与第 1 条同源：两处用不同形状描述同一个模型
   （清单给相对路径 `Krea2/krea2_turbo.safetensors`，loader 节点可能只写裸文件名），
   再用**字符串相等**去比，于是永远不相等、用户被拒。
   现在抽出一个归一化函数 `model_basename()`/`model_key()`，`/` 与 `\` 都当分隔符，
   服务端校验、清单输出、前端下拉三处统一走它；
   清单里每个工作流还直接带上 `compatible_models`（由校验用的同一方法算出），
   前端不再自己重写一遍过滤逻辑——那正是两边漂移的原因。

验证方式：352 项 unittest 全过（1 项跳过），外加一个把**真实 `app.js`**
装进手写 DOM 跑的无头检查 `run/check_review_ui.py`（10 项全过）。
后者能钉住第 5 条这种"要看交互才知道"的缺陷——它明确断言切回预览时 URL 里
仍带着图片路径。两个沙箱坑也记在文档里：`vm` 里顶层 `let` 不进全局对象、
本环境禁止嵌套起进程。
   `prompt()` 调用已全部清零，并有测试盯着不许回来。

测试从 320 项增加到 **344 项**，全部通过（1 项跳过）。（成图落盘那一轮结束时为 352 项。）

## 负面提示词注入修复（本轮追加）

承接上文"负面编码的连接点被占用还能不能继续"的讨论与查验，本轮修掉五项问题，
详见 [修复记录](docs/13-负面提示词注入修复记录.md)。**结论先行**：你填的负面词
**每次都进了提交图**；在极清流上看不到效果，是那条流 `cfg=1.0` 的数学结果
（CFG 公式退化为 `out = pos`，负项被消掉），不是注入缺陷。

1. **语义变更不再静默**。负面口挂的不是 `CLIPTextEncode`（如 `ConditioningZeroOut`，
   作者用它表示"不做负面引导"）时，填写负面词会把作者的设计换成真负面引导——
   原来 `errors`/`warnings` 全空。现在 `_negative_anchor_types()` 同时支持 **API 图与 UI 图**
   （UI 图的 `negative` 是 link id，要经 `links` 表解析），产出 warning 与
   `negative_prompt.replaces`。**只提示，不改行为。**
2. **负面编码节点不再重复创建**。原来 `updated_encoders` 去重集合只在"就地改写"分支
   写入，"新建"分支不参与，于是每个采样器各建一个内容相同的节点（实测 `[30]`、`[31]`）。
   现在按 `(负面文本, CLIP 连线)` 复用：两者都相同才合并。
3. **无 widget 声明时不再静默丢词**。新增 `BUILTIN_WIDGET_ORDER` 兜底表（15 类核心节点），
   在 `widget_order()` 里作为**最后兜底**，schema 永远优先。
   ⚠️ 表里必须写**声明顺序**——`_align_with_reason()` 已按位置插入隐藏的
   `control_after_generate` 槽位，表里若带上它，`KSampler` 的每个值都会错位一格
   （会炸出 `could not convert string to float: 'euler'`）。
4. **被绕开的 conditioning 节点会被指名，但不删**。`audit()["orphaned_conditioning"]`
   列出失去消费者的节点。该流含 3 个 rgthree `Fast Groups Bypasser` 控制的分支，
   删除有误伤风险，所以只标记。
5. **前端真相栏**显示 `自动写入或补建 CLIPTextEncode · 将替换 ConditioningZeroOut`。

> 关于上一轮查验报告（`docs/11`）里的「问题 4」：**已被 `docs/12` 更正**。
> 真实 ComfyUI 导出的 UI 图自带 `inputs[].widget` 声明，绑定与注册表无关，
> 所以那条结论只在"手写/第三方转换的、省略 `widget` 键的图"上成立。
> `docs/11` 按原样保留以留存查验过程。

## 种子与重做的关系

| 重做方式 | 种子 | 说明 |
|---|---|---|
| `same_seed` 同种子 | **保持不变** | 重发上一次的提交图，种子与全部参数逐一相同 |
| `new_seed` 换种子 | 重新随机 | 重新编译；即使批次固定了种子也会释放，确保真的换种子 |
| `edited_prompt` 改提示词 | 重新随机 | 只替换该条提示词 |
| `reupscale_only` 仅重做放大 | 重新随机 | 以上次输出作为输入图片 |

也可以直接给某次重做指定种子（抽屉与接口都支持），用于“只变种子、其它全不变”。

## 运行

```bash
# 正常使用：读写成 %LOCALAPPDATA%\ComfyBatch-S\，与打包版一致
python src/comfybatch_v2_app.py --port 8790

# 开发/联调隔离：数据写到 run\，完全不碰用户已有的预设与 LoRA 档案
python src/comfybatch_v2_app.py --port 8790 --data-dir ./run

# 与正式实例并行运行（单实例锁按名字隔离）
python src/comfybatch_v2_app.py --instance-name dev --data-dir ./run

# 已有实例失去响应时强制启动
python src/comfybatch_v2_app.py --force-new-instance

# 测试
python run_tests.py            # 或 python run_tests.py -v
```

常用参数：`--data-dir` 隔离数据目录、`--instance-name` 单实例锁命名空间、
`--force-new-instance` 强制启动、`--comfy-url` 覆盖 ComfyUI 地址、`--no-browser` 不自动开浏览器。

界面默认在 `http://127.0.0.1:8790/`。数据目录、审核记录与节点定义缓存都随 `--data-dir` 走。
