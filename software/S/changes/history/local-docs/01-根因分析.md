# S / ComfyBatch V2.14 根因分析报告

分析对象：`▶▷Krea2-极清生图流+SeedVR2-int8图像放大.json` 在“高清重绘2”分支 45 条全部失败。
证据来源：`S-研发资料包-2026-09-14-v1/07-关键运行报告/新极清工作流-45条失败-report.json`，
以及本次对真实工作流文件与真实 ComfyUI（`0.33.0`，`127.0.0.1:8188`）的实测。

---

## 一、结论摘要

计划书写的是“`UltimateSDUpscale` 的 UI 参数转换发生位置错位”。这个描述方向正确，但把它当成
单个节点的特例。实测表明它是一整类结构性缺陷：**位置游标在原理上不可能正确**。除此之外还发现
三个独立缺陷，其中一个（预设比例标签非法）会让 9 个内置规格中的 5 个必然失败。

| # | 缺陷 | 性质 | 状态 |
|---|------|------|------|
| 1 | 控件值位置游标漂移 | 结构性，影响所有含“已转连线控件”或“隐藏控件”的节点 | 已修复（改为按名字绑定） |
| 2 | 负面提示词漏掉 `KSamplerAdvanced` | 独立缺陷，二采流程负面词被静默丢弃 | 已修复 |
| 3 | HTTP 400 正文被丢弃 + history 错误不判定 | 独立缺陷，真实原因丢失且每条空转 30 分钟 | 已修复 |
| 4 | 5 个内置图像规格使用非法比例标签 | 独立缺陷，选中即必然 400 | 已修复 |
| 5 | 资源清单不校验（放大模型从未枚举） | 独立缺陷，缺失资源只能靠 ComfyUI 拒绝才发现 | 已修复（四层预检） |

## 二、缺陷 1：控件值位置游标漂移（45 条失败的主因）

### 缺陷代码

`comfybatch_v2_core.py:1153-1159`（V2.13）：

```python
widget_index = 0
for item in node.get("inputs") or []:
    if item.get("link") is None and item.get("widget") and widget_index < len(widgets):
        inputs[...] = widgets[widget_index]
        widget_index += 1
```

游标**只为“未连线”的控件输入**前进。但 ComfyUI 导出的 `widgets_values` 有两件事与这个假设冲突：

1. **已被转成连线的控件，其值仍保留在 `widgets_values` 里**。游标跳过它，槽位却不跳过。
2. **存在没有 API 输入的隐藏控件**（典型是 `control_after_generate`）。它占一个槽位，却永远不被游标消费。

### 实测证据

真实工作流中 `UltimateSDUpscale` 节点的声明（节选自工作流文件）：

```
inputs[] 顺序：image, model, positive, negative, vae, upscale_model,
              upscale_by(link=8), seed(link=9), steps, cfg, sampler_name,
              scheduler, denoise, mode_type, tile_width(link=10), tile_height(link=11),
              mask_blur, tile_padding, seam_fix_mode, ...
```

`widgets_values` 长度为 **21**，而带 `widget` 标记的输入只有 **20** 个——多出的 1 个正是
`seed` 后面的 `control_after_generate`。

游标实际分配结果：

| `widgets_values` 槽位 | 真实含义 | 游标把它写给了 |
|---|---|---|
| 0 | `upscale_by`（已转连线 8） | 跳过 |
| 1 | `seed`（已转连线 9） | 跳过 |
| 2 | `control_after_generate`（隐藏） | 跳过 |
| 3 | `steps` = 4 | `steps` 拿到 `widgets[0]` = `2.0` |
| … | … | … |
| 9 / 10 | `tile_width` / `tile_height`（已转连线 10/11） | 跳过 |
| 11 | `mask_blur` = 16 | `mask_blur` 拿到 `widgets[6]` = `'simple'` |

偏移量在**同一个节点内从 3 漂移到 5**。后果：

- `sampler_name` 收到 `'randomize'`（`control_after_generate` 的取值），不在采样器候选列表里；
- `scheduler` 收到整数 `4`；
- `denoise` 收到字符串。

ComfyUI 校验失败 → `HTTP 400`。而 `ComfyClient` 丢弃正文，于是 45 条全部只报
`HTTP Error 400: Bad Request`，且因为工作流级错误没有首错停止，同一错误被提交 45 次。

### 修复

改为**按名字绑定**（`src/comfybatch_nodeschema.py` 的 `WidgetBinder`）：

1. 以节点自己声明的控件顺序（`inputs[].widget.name`，对该文件权威）为基准，
   与 `widgets_values` 逐槽对齐；
2. 唯一的位置规则是“seed 类控件后面会插入一个隐藏的 `control_after_generate`”，
   且该规则由**对齐后的长度校验**兜底；
3. **再按名字覆盖连线输入**，因此“控件是否已转连线”不再影响任何其他参数；
4. 长度不符时**报结构化问题并列出两边清单**，绝不静默错配。

### 验证

真实工作流 + 真实 2848 节点 schema，节点 3 的绑定结果：

| 参数 | 旧游标写出 | 现在 |
|---|---|---|
| `steps` | `2.0` | `4` |
| `cfg` | `999` | `1.0` |
| `sampler_name` | `'randomize'` | `'euler'` |
| `scheduler` | `4` | `'simple'` |
| `denoise` | `1.0` | `0.15` |
| `mode_type` | 错位 | `'Linear'` |
| `mask_blur` | `'simple'` | `16` |
| `tile_padding` | 错位 | `64` |

`tests/test_compiled_graph.py` 以黄金值锁定这组结果。

## 三、缺陷 2：负面提示词漏掉 `KSamplerAdvanced`

`comfybatch_v2_core.py:1315`（V2.13）：

```python
sampler_ids = cls._node_ids(graph, "KSampler")
```

只遍历 `KSampler`。二采工作流用的是 `KSamplerAdvanced`，于是**负面提示词既不写入也不报错**——
`capabilities` 只检查“存在 `CLIPTextEncode`”，所以预检照样通过。用户填写了“三视图、多人”等
负面词，实际一个都没生效，而且没有任何提示。

修复：同时遍历两类采样器，并把报错信息从写死的 `KSampler {id}` 改为按实际节点类型输出。

## 四、缺陷 3：错误正文丢失 + 执行失败不判定

### 3.1 400 正文被丢弃

```python
with self.opener.open(request, timeout=timeout) as response:
    return json.loads(response.read().decode("utf-8"))
```

`urllib` 对 4xx/5xx 抛 `HTTPError`，而 `.read()` 从未被调用——**ComfyUI 的正文被直接扔掉**。
正文里恰恰含有节点号、出错值、合法候选列表。

修复：网关读取 `HTTPError.read()`，解析后作为 `ComfyError` 抛出并保留原始文本
（`src/comfybatch_gateway.py`）。

### 3.2 执行失败被当成“还在运行”

`output()` 只从 `/history/<id>` 里找图片。节点在 ComfyUI 内部抛异常时，history 里
`status.status_str == "error"` 且没有图片——与“还在跑”无法区分。于是一个失败的条目要
**空转满 1800 秒**才报超时，然后对下一条重复同样过程。

修复：`ComfyGateway.poll()` 返回 `pending | done | error` 三态，遇到 `status_str == "error"`
立即用 `ErrorTranslator.from_history()` 判定失败。实测失败判定从 **1800 秒降到秒级**。

### 3.3 错误类型键

实测 ComfyUI `0.33.0` 的真实类型串与猜测不同，已按实测校正：

| 场景 | 真实 `error.type` |
|---|---|
| 节点未安装 | `missing_node_type`（不是 `invalid_prompt`） |
| 组合值不在候选列表 | `value_not_in_list` |
| 必填输入缺失 | `required_input_missing` |
| 连线类型不匹配 | `return_type_mismatch` |
| 没有可执行输出 | `prompt_no_outputs` |

另外 `input_config` 的形状是 `["COMBO", {"options": [...]}]`（0.33），**不是**旧版的
`[[候选...], {...}]`；且候选很多时 `input_config` 为 `null`，只能从 `object_info` 补全。

## 五、缺陷 4：5 个内置图像规格使用非法比例标签

`ResolutionSelector` 的真实候选列表（实测）：

```
1:1 (Square), 2:3 (Portrait Photo), 3:2 (Photo), 3:4 (Portrait Standard),
4:3 (Standard), 9:16 (Portrait Widescreen), 16:9 (Widescreen), 21:9 (Ultrawide)
```

V2.13 的 `IMAGE_PRESETS` 中有 5 个标签**不在这个列表里**：

| 预设 | 旧标签（非法） | 修正为 |
|---|---|---|
| `landscape-m` | `3:2 (Landscape)` | `3:2 (Photo)` |
| `classic-m` | `4:3 (Landscape)` | `4:3 (Standard)` |
| `portrait-s/m/l` | `9:16 (Portrait)` | `9:16 (Portrait Widescreen)` |

选中这 5 个规格中的任何一个，`aspect_ratio` 写入后必然触发 `value_not_in_list`。
`tests/test_image_presets.py` 现在把全部 9 个规格逐一对真实 schema 校验。

## 六、缺陷 5：资源从未被校验

- `models/upscale_models` **从未被枚举**，所以缺失的 `OmniSR_X4_DIV2K.safetensors`
  只能等 ComfyUI 拒绝才发现（实测该机 `upscale_models` 下只有
  `RealESRGAN_x4plus_anime_6B.pth`）。
- LoRA 存在性未校验，且 `lora_name` 原样写入。ComfyUI 需要相对于 `models/loras` 的路径，
  子目录 LoRA 必然失败。实测 `/models/loras` 返回的正是这种相对路径
  （如 `Krea2-功能\QuadView_krea2_v1.safetensors`），因此清单改为优先取 `/models/{folder}`。
  这一点很重要：该机 LoRA 根目录由 `extra_model_paths.yaml` 指向
  `E:/模型（放入models）/loras`，只扫文件系统会漏。
- 编译后的参数值域/候选未校验。

修复（四层预检的第 2、3、4 层）：

1. 结构：节点、连线、分支、输出链路；
2. 资源：`/models/{folder}` 合并清单 + 文件系统兜底；
3. 参数：类型、范围、候选值对照 `object_info`；
4. 编译结果：`CompiledGraphAudit` 对**最终提交图**逐输入校验，含必填输入缺失与悬空连线。

## 八、本次额外发现并修复的缺陷

| 缺陷 | 说明 |
|---|---|
| `Image Comparer (rgthree)` 等纯显示节点被误判为需要绑定控件 | 它没有任何控件输入，却存放前端预览 URL。现在识别为「无控件」直接跳过，不报问题 |
| `Seed (rgthree)` 声明 1 个控件却有 4 个值 | 多出的是前端状态。现在区分「多出尾值」（警告）与「参数拿不到值」（阻断） |
| 提交图缺少必填输入 | 新增对 `required` 段的检查，把 ComfyUI 的 `required_input_missing` 提前到预检 |
| 三个审图接口重复读取请求正文导致永久挂起 | `do_POST` 已消费正文，重复 `_read_json()` 会阻塞在 socket 上。已修复并加静态与真实请求双重测试 |
| 重启后结果页空白 | 审核决定在磁盘上，但运行态在内存里。现在启动时恢复最近一次运行（标记为 `restored`） |
| 测试基线本身不成立 | README 写“50 通过 + 1 跳过”，实际 50 项中 3 项因 HTML 路径假设失败；已修正为可运行的基线 |
