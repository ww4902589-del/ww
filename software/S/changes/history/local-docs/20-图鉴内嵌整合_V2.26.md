# V2.26：把风格图鉴真正装进 S 里（2026-10-03）

## 现象

启动 S 之后切到「风格图鉴」模块，看到的不是图库，是一张引导卡：

> 图鉴服务未启动 —— 请双击桌面的「风格图鉴-打开.cmd」，启动后点「重新连接」。

用户的原话是：「它们组合为一个完整的程序，而现在，启动了一个，另一个需要我再去点击，那就没有组合的必要了」。

## 根因：组合只发生在界面层

`app.js` 里的 `ensureAtlas()` 探测 `127.0.0.1:8793`，探到了就把图鉴页 `iframe` 嵌进来；探不到就显示引导卡。**S 从来没有启动过图鉴**——它只是「找」图鉴。真正的图鉴是另一个独立进程：

```
tools/风格图鉴.cmd → atlas_open.py → 风格图鉴.py → subprocess → atlas_server.py --port 8793
```

而那个启动器依赖本机装好的 Python 解释器（`PY_CANDIDATES` 里写死了
`C:\Users\wyj\.workbuddy\binaries\python\versions\3.13.12\python.exe`）。

更硬的一条证据在打包配置里：改动前的 `src/S.spec` 里

```python
datas=[('index.html','.'),('app.css','.'),('app.js','.'),('default_presets.json','.')],
hiddenimports=[],
pathex=[],
```

四个前端文件，没有任何一项指向 `tools/`。**打出来的 exe 里根本没有图鉴代码**。
所以"组合"两字此前只存在于文案和 iframe 上：两个程序，两次启动，
换个没有那个 Python 的机器连启动器都跑不起来。

## 为什么是内嵌，不是拉起子进程

S 是单文件 exe，`sys.executable` 就是自己，没有解释器可以指。子进程方案要么再随包发一份
Python，要么让 `S.exe --atlas` 再解包一次自己（每份实例一个 `_MEIPASS`，慢且占空间）。

而图鉴服务本身就是一个标准库 `ThreadingHTTPServer`，直接在同进程起线程最干净：

* 一个 exe、一次双击，两个模块都在；
* 生命周期天然一致 —— S 退出 8793 跟着消失，不留占端口的孤儿（实测见下）；
* 前端探测逻辑一行不用改，8793 仍在原处，iframe 照旧嵌入。

## 改动

### 1. 状态落盘目录与代码目录解耦（`tools/style_atlas.py`）

内嵌的前提。打包后 `__file__` 落在解包临时目录（`_MEIPASS`），往那儿写
`_marks.json` 等于每次退出都把用户的标记清零。新增 `resolve_data_dir()`：

| 场景 | 数据目录 |
|---|---|
| `ATLAS_DATA_DIR` 环境变量 | 该路径（联调隔离用） |
| 打包运行（frozen） | `%LOCALAPPDATA%\ComfyBatch-S\atlas` |
| 源码运行 | 图鉴自己的目录（**原行为不变**，命令行用法零影响） |

`CACHE`（`_img_index.json`）跟着数据目录走 —— 留在代码目录就永远是空的，每次启动白扫一遍盘。

### 2. 图鉴服务可被外部宿主调用（`tools/atlas_server.py`）

* 拆出 `serve(host, port, ..., bootstrap=, log=)`，返回 `(server, http_thread)`；
  `main()` 改为调用它 + 前台阻塞。命令行行为不变。
* `bootstrap="background"`：**先绑端口**，再在后台线程建索引。
  顺序是刻意的 —— 反过来（先建索引后绑端口）的话，8793 被别的程序占着时
  这边会先白扫二十多秒的盘才轮到 bind 报错。这个错序是写测试时才发现的。
* `_resource()` 找只读模板（`compare_live.html`）：源码目录 → 解包目录，两级兜底。
* 建索引期间访问 `/` 端出**自动刷新的等待页**，而不是
  「风格图鉴.html 未生成，请先运行 build_atlas.py」—— 内嵌之后用户没有这个动作可做。
* `/api/version` 在窗口期就能应答（`building=true` / `images=0`），
  前端据此判断「该等」还是「该报错」。
* `_marks.json` / `_grades.json` / `风格图鉴.html` 全部改落到 `DATA_DIR`。

### 3. 宿主层（**新增** `src/atlas_host.py`）

`start(port=8793)` 的语义，按优先级：

1. 8793 上已有图鉴（`/api/version` 认得）→ **复用，不抢绑**，`embedded=False`；
2. 否则在同进程 `serve(bootstrap="background")`，`embedded=True`；
3. 端口被非图鉴程序占着 → 明确失败并给出原因（不静默降级）。

`start()` **不抛异常**：它跑在主程序启动路径上，抛出去就是一个起不来的 S。
失败原因写进 `数据目录/_atlas_host.log`（`console=False` 的 exe 里 `print` 是黑洞，
这行日志是「图鉴打不开」时唯一的证据）。

首次运行会把随包发的 `_marks.json` / `_grades.json` 副本铺进数据目录（`_seed_user_data`）。

### 4. 接线（`src/comfybatch_v2_app.py`）

`main()` 里 8790 `ThreadingHTTPServer` 建好之后、`serve_forever()` **之前**调用
`start_embedded_atlas()`。位置是硬约束：放到 `serve_forever()` 后面就永远执行不到。
`COMFYBATCH_NO_ATLAS=1` 可关闭（测试/联调要能拿到干净进程）。

版本号 `2.25` → `2.26`（`index.html` 三处同步，否则版本一致性测试会拦）。

### 5. 打包（`src/S.spec`）

```python
TOOLS = os.path.normpath(os.path.join(SPECPATH, '..', 'tools'))
pathex=[TOOLS],
datas=[..., (TOOLS/'compare_live.html','.'), (TOOLS/'_marks.json','.'), (TOOLS/'_grades.json','.')],
hiddenimports=['atlas_server','style_atlas','build_atlas','build_thumbs','atlas_host'],
```

从 `SPECPATH` 推绝对路径而不是写 `'../tools'`：spec 里的相对路径会跟着调用
PyInstaller 时的工作目录走，换台机器构建就指错。

### 6. 前端（`src/app.js` / `src/index.html`）

`ensureAtlas()` 从「探测 → 引导用户去启动」变成「探测 → 等它建好 → 嵌入」：

* 服务在线但 `building` / 0 张图 → 提示「图鉴正在建立索引（首次约 30 秒）」并自动重试，
  用户不需要做任何动作；
* 连不上 → 1.2 秒后自动重试，最多 60 次（约两分钟）；
* 重试到上限才报错，并指向 `%LOCALAPPDATA%\ComfyBatch-S\atlas\_atlas_host.log`。
* 离开模块（`suspendAtlas`）时停掉轮询定时器，否则切回工作台后它在后台空转。
* 「请双击桌面的『风格图鉴-打开.cmd』」这句从界面里彻底删除。

## 遗留

- **两份标记数据的分叉**。S 内嵌的图鉴用 `%LOCALAPPDATA%\ComfyBatch-S\atlas`，
  而 `tools/风格图鉴.cmd` 走源码运行的规矩，仍用 `tools/`。首次播种后两份内容一致，
  之后各自演化 —— 在 S 里标的图，用命令行启动器看不到（反之亦然）。
  日常入口是 S，所以实际影响小；真要统一，让启动器在
  `%LOCALAPPDATA%\ComfyBatch-S\atlas` 存在时跟随它即可（约 6 行）。
  本次没动它，因为「哪个入口是主入口」是产品决策，不该由一次修复顺手定。
- **watch 线程现在总是开着**。原来图鉴只在用户手动启动时跑，内嵌后每 20 秒
  全盘扫一次（Desktop / D:/liu / E:/工作流）判是否有新图。代价是常驻的轻量 IO。
  想省掉可以在 `start_embedded_atlas()` 里把 `watch_interval` 传 0，
  让「出图完成」那条通知（`atlasRebuild`）单独负责重建。
- **`style_atlas.py` 读 `report.json` 时不关文件**（`json.load(open(p))`，多处），
  跑一次扫描会刷出上千条 `ResourceWarning`。与本次改动无关，但它在测试输出里很吵。
- **`tools/` 下仍有 8 个 `atlas_server.py.bak_*` / `build_atlas.py.bak_*`**，
  以及两套并存的启动器（`风格图鉴.cmd` / `启动风格图鉴.bat`）。等内嵌版稳定一段时间后
  可以收拢，现在不动 —— 它们还能当独立调试入口用。
