## 一、问题 2：文件夹分类把中间的目录名吞了

### 症状层事实

- 那批图的实际位置：`C:/Users/wyj/Desktop/D/T/926266f5/…`（94 张，`D/926266f5` 92 + `D/a118df08` 2）。
- 时间分类里看得到：`facets.day` 的 `10-02` 正好 94 张，`run_time['926266f5']='10-02'`。
- 文件夹分类里 `D/T/…` **一项都没有** —— 不是图丢了，是分类名跟磁盘对不上号。

### 真因

`style_atlas.folder_of()` 旧实现在「猜哪一段像批次目录」：

```python
for seg in reversed(s[:-1]):          # 从父目录往上
    if _is_batch_dir(seg): pick = seg; break
```

`_is_batch_dir` 的规则里第一条是 **8 位 hex**。`926266f5` 命中 → 直接返回它；
而中间的 `T` 不命中任何规则，被跳过。结果：

| 磁盘真实路径 | 旧分类 | 说明 |
|---|---|---|
| `Desktop/D/T/926266f5/x.png` | `D/926266f5` | 中间的 `T` 被吞 |
| `Desktop/c/D/S-v2.14/run/probe-out/x.png` | `c/probe-out` | 吞掉 `D/S-v2.14/run` |
| `Desktop/c/ComfyUI集中整理_…/Krea2宣传片人物_三轮/第2轮/x.png` | `c/第2轮` | 吞掉两层 |

注意这个失败是**静默的**：标签看起来依旧「像个文件夹」，只是它不对应磁盘上的任何一级。
用户是按资源管理器找图的，界面上的名字对不上，就等于分类失效。

### 修法

不再猜哪一段「像批次」，直接取「扫描根之后、文件名之前」的**完整相对路径**：

```python
for i, seg in enumerate(s[:-1]):
    if seg in _ROOT_HINTS:            # Desktop / 工作流 / liu
        rel = s[i + 1:-1]
        return "/".join(rel) if rel else parent
```

配套三处：

1. **`FOLDER_RULE = 1`** —— `folder` 是**派生列**，规则变了 `build_id` 不会变
   （`build_id` 只认图集内容）。于是有两个静默洞：① 磁盘上的
   `_data_cache.json` 会被当成新数据端上来（用户看到的还是旧分类）；
   ② 页面轮询 `build_id` 发现没变就不刷新。把这个常量**喂进指纹**
   （`_fp.update("folder_rule=%d")`）并写进 payload，两个洞一起堵。
2. **`atlas_server._preload()` 校验 `folder_rule`** —— 版本不符就当没有缓存，
   老实重算（多等一次构建，也不要端错数据）。
3. **`build_atlas.folderLabel()`** —— 二级按钮只有 58px 宽，真实层级后标签变长。
   二级列表本来就只在选中的大文件夹之下出现，第一段（`D`/`c`）已经由上面那排
   表达过了，于是剥掉它，让 `T/926266f5` 这种真正用来认路的段露出来；
   过长时保留头尾（`D/S-v2…be-out`），完整值在 `title` 里。

## 二、问题 1：对比页看不到标记状态

### 症状层事实

`tools/compare_live.html` 里**完全没有标记相关代码**：
`grep -c "★\|marks\|标记"` = 0。标记系统只存在于图鉴侧
（`_marks.json` + `localStorage` + `build_atlas.py` 的 ★/右键菜单）。
图鉴把一批图推给对比页时，`POST /api/selection` 只带了 `path/preset/styles/loras`，
**没带 uid** —— 对比页连「这张图是哪一张」都对不齐标记。

### 修法

1. **服务端**：`POST /api/selection` 的每条 item 补 `uid`
   （`path#批次#序号`）。只给 path 的话，跨批次的同名图会互相认错 ——
   图鉴那边正是因为这个才引入 uid。
2. **对比页**：拉 `/api/marks`，做 `uid` 精确 + `path` 兜底两条索引
   （`MK_UID` / `MK_PATH`，与图鉴 `uidPath()` 同一口径，兜「图鉴重建后 uid 漂移」）；
   色号用与图鉴**同一套** `COLORS`（`#e05a4f` 起 7 色），夹的颜色在两个页面一致。
   呈现四处：卡片上的 `★ 夹名` 签、卡片边线、顶栏「已标记 N / M 张」+ 各夹计数、
   灯箱标题栏的 `★ 夹名`；再加一个「只看已标记」开关。
3. **只读，不写**。写协议是「整体覆盖 sets」（前端是权威），图鉴页常开着、
   手里有一份内存副本，对比页再写一次会把先写的整份盖掉 ——
   用户看到的是标记随机丢失。所以对比页只显示，改标记回图鉴。
   这条有测试钉着（`test_compare_page_only_reads_marks_never_writes_them`）。

实现时的一个连带修正：引入「只看已标记」后，`ITEMS`（全量）与视图下标会错位，
卡片上的「⇢ 导入工作台」原来按 `ITEMS[i]` 取图，过滤后会导错图。
改成 `VIEW`（视图位置表）+ `ITEMS[VIEW[pos]]`，分页与灯箱翻页也都走 `VIEW`。

## 三、被推翻的假设（留档）

- **「`cache:'no-store'` 会触发 CORS 预检」**（V2.29 的旧结论，本轮继续作废）：
  真 Chromium 实测只给请求补 `Cache-Control: no-cache` / `Pragma: no-cache`，
  **不发 OPTIONS**。对比页新加的 `/api/marks` 取用同源请求，与此无关。
- **「文件夹分类的根因是 `_is_batch_dir` 的关键词表不全」**：不是。
  关键词表再全也救不了 —— 这个设计的本质是「只保留一段」，
  只要中间有目录名不命中规则就会被吞。要修的是「取完整相对路径」这件事本身。

## 四、教训

1. **派生列的算法变了，必须同时作废「缓存」与「指纹」**。
   `folder` 不影响图集内容 → `build_id` 不变 → 缓存端旧值 + 前端不刷新，
   两处都静默。给派生规则一个版本号，同时喂进指纹和预载校验，才是完整修法。
2. **「猜哪一段像 X」的启发式，失败方式是静默的**。它总能返回一个
   「看起来像文件夹」的字符串，所以没有任何一层会报错。改成
   「取真实子路径」之后，可以写一条**形式化护栏**——标签必须原样出现在路径里
   （`"/"+label+"/" in path`），把这整类错误一次性挡掉。
3. **加筛选视图时，先检查所有按下标取数据的地方**。
   `ITEMS[i]` 在引入 `VIEW` 之后全部要改成 `ITEMS[VIEW[i]]`，
   否则过滤状态下会「看着是这张、导的是那张」——比功能缺失更坏。
