> 2，绿色框，保留。注意标记的按钮的位置和大小」

## 一、为什么要换协议，而不是把「只读」改写成「可写」

V2.31 特意钉了一条护栏（`test_compare_page_only_reads_marks_never_writes_them`），
理由是**真实存在的数据事故**：

| 页面 | 手里有什么 | 写协议 | 后果 |
|---|---|---|---|
| 图鉴页 | 全量 sets（它就是权威） | `POST /api/marks` 整体覆盖 | 正常 |
| 对比页（旧设想） | 加载时的一份快照 | 同上 | **把图鉴期间新标的图全抹掉** |

所以问题不是「要不要让对比页能写」，而是「用哪种协议写」。答案是
**换协议**：新增 `POST /api/marks/apply`，语义是「这几张图 → 加进/移出这个夹」，
服务端现读现改。两条写路径共用模块级 `_marks_lock`。

护栏因此被有意改写，但**它守护的目标没变**：

```python
# 旧护栏（V2.31）：对比页一个字都不许写
self.assertNotIn("/api/marks',{method:'POST'", code)
# 新护栏（V2.32）：不许整体覆盖（这才是会吃数据的那个动作），但允许局部 apply
self.assertNotIn("/api/marks',{method:'POST'", code)   # ← 保留
self.assertIn("/api/marks/apply", code)                # ← 新增
```

禁的是「整体覆盖」，不是「写」。宁可少一个功能，也不要一个会吃数据的 —— 这条原则保留。

### 过程中被真验证抓到的三个坑

1. **`self._marks_lock` 崩溃**：第一版把锁写成实例属性。`Handler` 是**每请求新建**的，
   挂 `self` 上的锁形同虚设（每次请求一把新锁）。真起服务打请求直接
   `AttributeError`。改成模块级 `_marks_lock` 后才通 —— 这条已经写进测试断言
   （`assertNotIn("self._marks_lock", ...)`）。
2. **验证脚本污染真数据**：第一版脚本只改 `S.DATA_DIR`，但 `marks_file` 取自
   `Handler.out_dir`（类属性，447 行从 `DATA_DIR` 赋值），于是测试夹
   `verdict-reject` 被写进了用户的真 `_marks.json`。已按备份还原
   （43 张、单夹、active 正确），脚本改为**同时**改两处并加隔离断言
   （`test_isolation_writes_to_temp_dir` 放在测试类最前面）。
3. **fixture 用假路径导致假阴性**：`GET /api/marks` 会过滤掉指向不存在文件的标记
   （`dropped`）。用 `C:/p/1.png` 这种假路径时，所有夹读回来都是空的，
   看起来像接口坏了。改用临时目录里真实创建的文件后全过。

### 第四个坑：负色号（前端逻辑验证抓出来的）

第一版前端这样算要回写的色号：

```js
color: MCOLORS.indexOf(VERDICT_COLOR[setId])   // 反查自定义色
```

而 `#d0402f` / `#2f8b57` **都不在** `MCOLORS` 里 → 反查得到 `-1`。
`-1` 是合法 int，被原样存进了 `_marks.json`。前端 `setColor` 有取模保护
（`((c%len)+len)%len`）所以界面上看不出问题，但图鉴页读这个值时
`MCOLORS[-1]` 在 JS 里是 `undefined` —— 色号脏了。

修法：显式给下标，不反查。

```js
const VERDICT_SLOT={[SET_DEL]:0,[SET_KEEP]:2};   // 红 0 号位、绿 2 号位
...
color: VERDICT_SLOT[setId]
```

显示色仍走 `VERDICT_COLOR` 钉死的红/绿，与写回后端的槽位解耦。

**这个坑是 Node 里跑前端真实函数（`tests/check_compare_verdict_js.js`，
22 项断言）抓出来的，不是靠读代码看出来的。**

## 五、教训

1. **「只读」这个决定后面往往藏着一条数据安全理由，改行为之前先把理由读出来。**
   这里真正的理由是「整体覆盖会吃数据」，不是「对比页不该写」。看清这一点，
   修法就从「解开护栏」变成「换协议」，护栏还能继续守着。
2. **测试断言也是代码，会把错误一起固化。** `self._marks_lock` 是我写的，
   测试里我也照着写了 `with self._marks_lock:` —— 两边同错，单测全绿。
   是**真起服务打请求**才炸出来的。护栏要断在语义上（锁必须模块级），
   不能照着实现抄。
3. **写文件的验证脚本，第一件事是证明它写的是临时文件。**
   这次真把测试数据写进了用户数据文件。加一条「写的是临时路径」的断言
   （挂在接口返回值上）比事后道歉便宜得多。
4. **fixture 要满足被测接口的前置条件。** `GET /api/marks` 有「文件必须存在」
   的过滤，用假路径就是制造假阴性 —— 断言失败时先怀疑 fixture。
5. **「反查 → 得到 -1 → -1 是合法值」是一类静默缺陷的固定形状。**
   凡是 `indexOf` 的结果要当作合法数据用，就得先想清楚查不到时那个
   `-1` 会被谁接手。这里的接手方是「取模保护」，它把错误藏得严严实实。
6. **多进程/多写入方共享一个文件时，锁要挂在进程级作用域上。**
   挂在请求对象上等于没有锁，而且失败方式很难看（AttributeError 或静默丢数据）。
