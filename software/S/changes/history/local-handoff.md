# S / ComfyBatch V2.41 交接

## 本次交付（V2.41）：修掉两处预设缺陷

用户报告（原话）：

> 「软件s 1，我在工作台的第一页中，能找到预设，但无法删除。
> 2，工作台第二页，找不到预设，但可以删除，且删除按钮全是白色」

两个症状各有独立的根因，都已修：

### 1）第二页「找不到预设」——启动读走了写接口

`app.js` 的启动序列调 `refreshInventory()`（= `POST /api/configure`）。它是写路由，
受编辑租约约束：第一个页面先启动拿到租约，第二个页面再启动就被 `409` 挡下，而这条
调用没有 `.catch`，异常被静默吞掉，`inventory` 保持为空 —— 所有预设下拉（含第二页）
全空。

修法：新增只读 `GET /api/inventory`（不在 `WRITE_ROUTES` 里，无需租约，返回体与
`POST /api/configure` 的 `inventory` 逐键一致），启动序列改走它并补 `.catch` 兜底。
`tests/test_live_sync.py` 的 `PresetSyncTests` 钉住了「读预设必须走只读接口」。

### 2）「删除按钮全是白色」——CSS 变量从未定义

`button.danger` 的规则里写着 `background:var(--danger)`，而 `--danger` 从来没在
`:root` 里定义过。`var()` 没有兜底值时整条声明在计算阶段失效，底色退回 `initial`
（透明），只剩基础 button 规则里的白字 —— 白字配透明底，整个按钮看起来消失。
浏览器实测：修复前 `getComputedStyle` 得到 `background:rgba(0,0,0,0)`，修复后
`rgb(201,74,90)`。

修法：`:root` 补上 `--danger:#c94a5a`（顺带补 `--line-strong`，同样被引用却未定义）。
`tests/test_page_assets.py` 的 `CssVariableTests` 会遍历所有被引用的自定义属性，
缺失即失败。

### 关于「第一页能找到预设，但无法删除」

第一页（文件与任务）是给已选提示词**分配**预设的地方，本来就没有删除按钮 —— 这是设计，
不是缺陷。预设的**增删改**在第二页（生成配置）。第二页修好后，预设可见也可删。
（若希望第一页也能直接删除，属新增交互，需要另行确认。）

### 3）第二页「预设名称」输入框改成预设菜单

用户反馈：第二页选预设要自己手输，而不是菜单。原因：第二页原本有两个控件 —— 网格里的
「风格／LoRA 预设」下拉（**真正**决定 更新/删除/重新载入 作用于哪个预设）和按钮栏里的
「预设名称」文本框（只用于显示/输入名字）。两者分开摆，文本框又紧挨着按钮，于是看起来
像「必须先手输预设」。

改法：把预设下拽菜单移进按钮栏（`presetPicker` 原样搬过去，网格里那一项去掉），删掉
「预设名称」文本框；「另存新预设」改为弹出输入新名称，其余按钮直接作用于菜单里选中的
预设。`.preset-command-bar select` 一并纳入 `min-height` 规则。

代价：不再能靠「改名 + 更新预设」重命名预设（「更新预设」现在沿用原名）。
随后按用户要求把重命名**加回来**：按钮栏新增「重命名」（`renamePreset()`），弹出输入框
并**预填当前名称**；改名只动名字、不动内容（沿用该预设已存的风格/LoRA，而不是当前篮子）。
按钮栏随之改为 7 列一行（`repeat(6,auto)`，媒体查询里的窄屏规则不变）。
本次**不升版本**（用户要求），仍是 V2.41，只改了源码并重新打包。

### 4）预设回收站：删除可恢复，恢复强制标记

用户要求（原话）：

> 「再墓碑中加入一条，从其中恢复预设，需要强制标出信息。」

三问定下的口径：入口放**预设栏（按钮 + 清单）**；恢复出来的名字用**「[恢复] 」前缀**
强制标记；现有 205 条只有名字、没有正文的旧墓碑**整体清空（= 清空回收站）**。

背景：墓碑原本只记 `{deleted_at, name}`，所以「从墓碑恢复」根本无正文可恢复 ——
要让恢复成立，墓碑必须先存正文。

改动：

- **后端 `src/comfybatch_v2_app.py`**
  - `delete_style_lora_preset` 的墓碑条目加 `preset`（删除前的完整正文）。
  - 新增 `restore_deleted_style_lora_preset`（沿用原 id、删墓碑、写实体，同一次写入）、
    `clear_deleted_style_lora_presets`（清空+报条数）、`_restored_name`（前缀 + 唯一化）。
  - 路由 `POST /api/restore-deleted-preset`、`POST /api/clear-deleted-presets`，两条都进
    `WRITE_ROUTES`；列表复用**既有**的 `GET /api/deleted-presets`。
  - **不升 `SCHEMA_VERSION`**：墓碑条目对 store 是不透明 dict，加字段向后兼容。
  - 「[恢复] 」前缀**只由后端加** —— 换任何入口恢复都带标记，这是「强制」的落点。
- **前端 `src/index.html` / `app.js` / `app.css`**
  - 预设栏加「恢复已删除…」→ `#trashDialog`（原生 `<dialog>`，与 `#capabilitiesDialog` 同路子，
    不碰 `hidden` 属性那条坑）。
  - `renderTrash` 每行给 名字 / 删除时间 / 内容条数 + 「恢复」；没有正文的旧记录不给按钮，
    只说明「无正文，无法恢复」；底部「清空回收站」。
  - 预设栏 6 列 → 7 列（`repeat(7,auto)`）。前缀不由前端拼。
- **测试**
  - 改写 `test_preset_store.DeletedPresetUiTests` 原有的三条「不许显示已删除」断言：改为断言
    回收站存在、使用那三条路由、且页面**绝不**拼前缀。旧的「no deleted panel」约束到此作废，
    理由是：那个约束要防的是「复活的预设看起来从没被删过」，而现在由**强制前缀**来兜。
  - `ApplicationPresetTests` 新增 8 条：墓碑存正文 / 恢复带前缀且内容一致 / 恢复后重启仍在 /
    无正文拒绝恢复 / 未知 id 拒绝 / 重名唯一化 / 清空落盘且报条数 / 两条路由需租约 /
    指纹随删除·恢复·清空翻转。
  - `test_app_routes` 的 GET 与 POST 枚举各补齐。

**两个后果（需知）**：①「清空回收站」会丢弃现有 205 条记录（含今天那 21 条），其中 7 条的
正文只在 `settings.backup-before-favfilter-*` / `before-coll3-import` 里，清空后不再可提；
② 清空等于移除这些预设的「防复活」记录 —— 已核对当前候选文件只有 `settings.json` 与内容

### 1）批次启动器 `src/comfybatch_launcher.py`（新增）

把外部 `guard_tup89.py` 那套能力收进程序：**一次导入 → 按画幅分组 → 逐组提交 → 断点续跑**。

| 收进来的东西 | 为什么不能留在外面 |
| --- | --- |
| 画幅分组 | 画幅标签必须与 ComfyUI `ResolutionSelector` 逐字节一致。外部脚本只能复制一份清单，已验证会漂。现在 `canonical_aspect_ratios()` 从 `IMAGE_PRESETS` 派生，不再有第二份字面量。 |
| 逐组提交 | 外部脚本靠 HTTP 打 `/api/start`，必须自己复制「准备配置→预检→建目录→起跑」的顺序并处理 400 预检负载。现在直接调 `BatchRunner.start`，与页面按钮同一条路。 |
| 断点续跑 | 判据是**输出目录里已存在的 PNG 编号**，不依赖任何内存状态。进程被杀后重来仍正确（外部脚本 01:48 被杀、只补 2:3 组这次就是这么恢复的）。 |
| 组间独立 | 一组失败不阻止下一组；但失败会在结果里如实记下（`status_failed`）。 |

关键决定：**不重排组内次序**（编号通常按设计主题排）、**同一时刻只允许一个分批任务**、
**不在这里做预检/编译/LLM**（那是 runner 与适配器的活）。

新增路由：`POST /api/launcher/preview`（只算分组）、`POST /api/launcher/start`、
`POST /api/launcher/cancel`；`GET /api/status` 的返回体新增 `launcher` 字段，
随既有轮询一起刷新，不额外发请求。

前端：`index.html` 「检查与运行」新增 `#launcherPanel`（可折叠），
`app.js` 新增 `launcherPreview / launcherStart / launcherCancel / renderLauncher`，

## 一、对比页显示标记状态

### 症状层事实

`tools/compare_live.html` 里**一行标记代码都没有**（`grep -c "★\|marks\|标记"` = 0）。

`path/preset/styles/loras`，**没带 uid** —— 对比页连「这张图是哪一张」都对不齐标记。

### 修法

| 层 | 改动 |
| --- | --- |
| `tools/atlas_server.py` | `POST /api/selection` 的每条 item 补 `"uid": im.get("uid")` |
| `tools/compare_live.html` | 拉 `/api/marks`，建 `MK_UID`（精确）+ `MK_PATH`（兜底）两条索引，色号复用图鉴 `COLORS`；卡片 `★ 夹名` 签 + 卡片边线 + 顶栏「已标记 N / M 张」+ 各夹计数 + 灯箱标题栏；新增「只看已标记」开关 |

**只读，不写。** 写协议是「整体覆盖 sets」（前端是权威），图鉴页常开着、
手里有一份内存副本，对比页再写一次会把先写的整份盖掉 —— 用户看到的是标记
随机丢失。所以要改标记还是回图鉴。这条有测试钉着

## 二、文件夹分类 = 真实目录层级

### 症状层事实

- 那批 94 张图在 `C:/Users/wyj/Desktop/D/T/926266f5/`（`D/926266f5` 92 + `D/a118df08` 2）
- 时间分类看得到：`facets.day` 的 `10-02` 正好 94 张
- 文件夹分类里 `D/T/…` **一项都没有** —— 图没丢，是分类名跟磁盘对不上号

### 真因

`style_atlas.folder_of()` 旧实现在「猜哪一段像批次目录」（8 位 hex / 含轮批套组 /
含中文 / 带日期），只回**那一段** + 根前缀。`926266f5` 命中 hex 就被返回，
中间的 `T` 不命中任何规则 → 被吞。同类的还有 `c/D/S-v2.14/run/probe-out` →
`c/probe-out`、`c/…/Krea2宣传片人物_三轮/第2轮` → `c/第2轮`。

这个失败是**静默的**：标签看起来依旧「像个文件夹」，只是不对应磁盘上的任何一级。

### 修法

不再猜，直接取「扫描根之后、文件名之前」的完整相对路径。
配套三处（这三处缺一都会静默出错）：

1. **`FOLDER_RULE = 1`** —— `folder` 是派生列，规则变了 `build_id` 不会变，
   于是：① 磁盘上的 `_data_cache.json` 会被当新数据端上来；
   ② 页面轮询 `build_id` 发现没变就不刷新。把它**喂进指纹**并写进 payload。
2. **`_preload()` 校验 `folder_rule`** —— 版本不符就当没有缓存，老实重算。
3. **`build_atlas.folderLabel()`** —— 二级按钮只有 58px 宽；二级列表只在选中的
   大文件夹之下出现，第一段已由上面那排表达过，于是剥掉它，
   让 `T/926266f5` 露出来；过长保留头尾（`D/S-v2…be-out`），完整值在 `title` 里。

### 验证
