## 一、改版前必须知道的三层防线

前端现在**没有视觉回归测试**，但有三种东西会在你改版时"突然红"。动第一行 HTML 之前先知道它们在哪：

| 防线 | 位置 | 它盯什么 |
|---|---|---|
| **结构基线** | `run/snapshot_frontend.py` + `run/frontend_baseline.json` | 每个阶段的 id/按钮/标签清单、设计令牌、断点、布局规则。改版后跑一次，**逐条确认 diff** |
| **DOM 行为检查** | `run/check_review_ui.py`（11 项） | 打回重做/记录问题对话框、预览路径、查看器切换、模型下拉。它跑**真实 app.js** |
| **资产级测试** | `tests/test_page_assets.py` | 脚本定界符平衡、审图界面要素存在性 |

**标准流程**：改 → `python run/snapshot_frontend.py`（看 diff）→ `python run/check_review_ui.py --emit-only` + `node run/_dom_harness.js src/app.js run/_dom_harness-result.txt`（11/11）→ `python run_tests.py` → 确认无误后 `--update` 重写基线。

### snapshot 工具的用法（本轮新增）

```bash
python run/snapshot_frontend.py            # 与基线比对，报告差异（有差异退出码 1）
python run/snapshot_frontend.py --update   # 改版确认后重写基线
python run/snapshot_frontend.py --emit     # 只打印当前快照
```

它抓的是**可枚举的结构事实**：六个阶段的 `ids`/`buttons`/`labels`/`inputs`/`selects`、
左侧导航条目、`--xxx` 设计令牌、`@media` 断点、`.workspace`/`.grid`/`.step-nav` 等布局规则。
diff 是**细粒度**的（按阶段逐字段比对集合差），不会一改动就报一整屏"面板变了"。

**它挡不住什么**：配色好不好看、间距舒不舒服。它挡得住的是：元素消失、阶段错位、
导航压住内容——`docs/08` 那六个缺陷里的三个布局类问题，都是这个形状。

## 二、当前结构速查（改版的对象）

### 2.1 六阶段与导航（结构已按真实 DOM 校准）

| 阶段 | 标题 | 面板容器 | 关键 id |
|---|---|---|---|

| 2 | 工作流 | （无容器 id） | `workflow` `workflowVariant` `workflowFingerprint` `actualBranch` `chainSummary` `ioSummary` |
| 3 | 模型、风格与 LoRA | （无容器 id） | `model` `styles` `loraPick` `loras` `presetPicker` `presetName` `styleLibrary` `styleName` `styleApplication` `stylePreview` `deletedPresets` |
| 4 | 参数工作台 | **`section#paramWorkbench`** | `globalImagePreset` `aspect` `paramScope` `paramScopeHint` `paramGroups` `applyParams` `paramFeedback` |
| 5 | 检查与运行 | （无容器 id） | `preflightButton` `effective` `progress` `maxRetries` `singleSubject` `llmEnabled` `llmKey` `llmModel` `llmTemp` `llmUrl` `abortBanner` |
| 6 | 成图与确认 | （无容器 id） | `start` `gallery` `reviewBoard` `reviewSummary` `backStep` `nextStep` |

**浮层**（不属于任何阶段，常驻顶层）：`drawer`（问题详情抽屉）、`viewer`（原图查看器）、
`rejectDialog`（打回重做）、`noteDialog`（问题记录）、`mappingDialog`（Excel 字段映射）。

### 2.2 ⚠️ 一个真实的工具陷阱（已修复，记录在案）

第一版 `snapshot_frontend.py` 的正则要求 `class` 紧跟 `<section`，
而阶段 4 的开标签是 **`<section id="paramWorkbench" class="…" data-step="4">`**——
`id` 在 `class` 前面，**整个面板被跳过**，参数工作台的 id 全被错误归进阶段 3。
第一份基线因此是错的（`docs/16` 初版据此写了"参数工作台 id 在阶段 3"的错误结论）。

已改为**整体匹配开标签、事后解析属性**，并加了三处防御：
① 容器自身的 id 并入面板 ids；② 最后一个面板的 body 以真相栏开头为界，
不再吞掉 main 外的浮层；③ 浮层单独成 `floating_panels` 清单。
基线已用修正后的工具重建。

**教训**：写"结构是什么"之前，先用工具的 `--emit` 对照源文件抽查一个面板；
工具本身就是第一版资料，基线结论要等工具经过一次自证再用。

## 四、改版"不许坏"清单

这五条是历史教训的硬约束，改版前后各查一遍：

1. **真相栏常驻**——任何阶段都能看到生效配置（改版后仍要覆盖五个阶段）。
2. **同屏只能有一个工作流指纹**——`docs/08` 修过的缺陷，合并面板时两处 facts 容易复制出两个指纹。
3. **阻断时真相栏不得自称"没有阻断问题"**——阻断态与预检态的渲染分支要过 `check_review_ui.py`。
4. **左侧导航不得压住内容**——六改五之后导航变矮，但要确认折叠态/窄窗口不遮按钮。
5. **`prompt()` 不许回来**——已有测试盯着；新增交互一律走 `<dialog>`。

## 六、参考来源

改版时可以从两类来源取参考：**项目内的**（权威，反映真实约定）与**外部的**
（成熟模式，借布局思路）。外部参考只借思路，不照抄样式——本项目已有自己的视觉语言
（米白纸面 + 红陶强调色 + 深色导航栏），改版应保持。

### 6.1 项目内来源（第一优先）

| 来源 | 内容 | 用途 |
|---|---|---|
| `run/frontend_baseline.json` | 六阶段真实结构快照（ids/按钮/标签/令牌/断点） | **权威结构事实**，画任何设计稿前先看它 |
| `docs/08-前端重新规划.md` | 六阶段信息架构与真相栏的**原始设计理由** | 明白"为什么当初这样分"，合并阶段时才不破坏初衷 |
| `docs/16` 本文 §2、§4 | 结构速查 + 不许坏清单 | 动刀前逐条过 |
| `run/mockup-stage24.html` | 阶段 2+4 合并方案的静态预览 | 布局提案的讨论底稿 |
| `src/app.css:1-3` 分段注释 | 样式表的区块地图（基础/卡片/画廊/…/抽屉/查看器） | 新样式该放进哪一段 |
| `run/check_review_ui.py` 头注释 | 11 项 DOM 检查与 vm 沙箱陷阱 | 改交互前先知道哪些行为被钉住 |

### 6.2 外部参考（借布局模式，不抄样式）

| 参考 | 对应本项目的什么 | 借什么 |
|---|---|---|
| **IDE 三栏布局**（VS Code、Figma 的检查器面板） | 左阶段导航 + 中主面板 + 右真相栏，正是同一构型 | 窄屏时检查器（真相栏）如何折叠/换行——1180px 断点已做，可对比成熟产品的处理 |
| **Material Design 的 Stepper 规范** | 六阶段工作流导航 | 关键结论：步骤应**可自由跳转**、已完成步骤可见状态。本项目已如此（非强制向导）；合并 2+4 后保持这一性质 |
| **语义化设计令牌**（Material Design 3 的 color roles、Radix UI Colors 的语义分层） | `:root` 的 7 个变量（bg/card/ink/muted/line/accent/green） | 现在的令牌已是"语义"而非"色值"命名，改主题只动 `:root`；若要加暗色主题，按这套语义对齐即可，不必新增散落色值 |
| **《Refactoring UI》（Wathan & Schoger）** | 卡片层级、间距节奏、强调色使用 | 实用规则：层级用字重与灰度而非加框；强调色留给"唯一主操作"。阶段 1 的按钮群（4+4 个 secondary）可据此收敛 |
| **NN/g 的 Wizard 与 Form 设计指南** | "频繁换工作流"场景下阶段 3.4 的取舍 | 支持本项目"明确不做强制向导"的判断：频繁使用者获益于自由跳转，向导只利于新手 |

### 6.3 使用顺序建议

1. 画新布局前：先 `snapshot_frontend.py --emit` 导出当前结构，对照 §2.1 表。
2. 出草稿时：布局问题查 §6.2 的 IDE 三栏与 Stepper（结构性），观感问题查 Refactoring UI（层级/间距）。
3. 落地前：过 §四 不许坏清单 → 三层防线全跑 → diff 逐条确认。
