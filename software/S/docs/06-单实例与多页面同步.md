# 多实例、事件流与编辑租约（P3）

这一轮修的是**唯一一个会丢数据的问题**：多个页面各自保存配置、互相覆盖。
（当时的另一项目标——「重复启动只激活同一个窗口」——已按用户要求撤销：现在多个窗口可以共存并共用一个数据目录，见第一节。）

---

## 一、多实例：多个窗口共用一个数据目录

> **本节已重写（2026-09-25）。** 原先这里是「单实例」：用 Windows 命名互斥体
> （`CreateMutexW` + `ERROR_ALREADY_EXISTS`）判断是不是第一个实例，第二个启动不再开
> 后端，而是 `POST /api/activate` 把已有窗口切到当前任务。用户明确要求允许多个窗口
> 共用同一数据目录，互斥体因此被移除；下面的内容是替代它的机制。

### 端口靠绑定抢占，不靠探测

先探测「这个端口空不空」再绑定，两步之间就是竞态：另一个进程可以在探测之后、绑定
之前把端口拿走，而失败要等到真正绑定时才暴露。所以现在**绑定本身就是检查**：
`bind_server()` 从首选端口开始逐个尝试 `bind`，成功即拥有，全部被占则抛出说明试过
哪些端口的错误（打包版没有控制台，这个错误还会弹一个消息框，而不是静默退出）。

一个只在 Windows 上成立的要点：`http.server.HTTPServer` 默认 `allow_reuse_address = 1`，
它允许**第二个进程绑定一个已经有人在监听的端口**——第二个绑定会成功，然后收不到任何
连接。那样「绑定即检查」就永远通过，两个实例会宣布同一个 URL。因此监听套接字用
`ExclusiveThreadingHTTPServer`：清掉 `allow_reuse_address`，并在绑定前设置
`SO_EXCLUSIVEADDRUSE`。前者已足以让同类服务器不能抢同一个地址（实测 100/100 被拒）；
后者是加固，堵住「对方设了 SO_REUSEADDR」与「持有具体地址时另一头绑通配地址」两种情形。

### 实例记录按进程分开

旧实现只有一份 `instance.json`，由所有进程共用：谁最后退出，谁就把描述另一个**仍在
运行**的进程的记录删掉；一份文件也只能描述 N 个进程里的一个。现在每个实例在
`%LOCALAPPDATA%\ComfyBatch-S\instances\<instance_id>.json` 写自己那条，退出时只删
自己那条。记录仍然**不放在 `--data-dir` 里**：它描述的是进程，不是某次启动所用的数据
目录，放在数据目录会让「换个数据目录启动」看不到已有实例。进程已不存在的记录由读取者
顺带回收（`GET /api/instances` 会列出活着的实例）；但存在一个宽限期，刚启动、端口还没
开始监听的实例不会被别的进程误删。

`/api/ping` 不再有 `is_primary`：多实例下没有任何一个是「主实例」，调用者用
`instance_id` 区分。`--force-new-instance` 保留但已废弃（现在每次启动都会新开实例），
传入只会打印一条说明，不会留下一个误导性的开关。

### 共享数据：唯一临时文件、原子替换、短时锁、修订号

单进程时每一处写入都用固定的 `<目标>.tmp` 当草稿文件。两个进程同时写 `settings.json`
就会写**同一个**草稿路径，然后 `os.replace` 发布“最后完成的那一份”，其中可能混合了
双方的内容。现在：

1. 草稿名按进程与调用唯一（`atomic_write_text`），写完 flush + fsync 再原子替换；
2. 读—改—写整体在短时文件锁（`FileLock`）内完成——锁只覆盖一次读加一次替换，**不会**
   长成刚被移除的那种全程单实例锁；
3. 设置文档带 `revision`，窗口保存时若磁盘修订已前进，保存被拒绝并提示
   「设置已被另一个窗口修改」，而不是回滚对方刚做的改动。

边界说清楚：锁是**按文件**的劝告性锁，只协调使用这套模块的 S 进程，不阻止编辑器或备份
工具改同一个文件；同一个键的并发写入仍然是「最后写者胜」——新增的保证是文件不会被写坏、
修订号不会丢、输的一方会被**告知**。

SQLite 作品库同样按「两个进程都可能开着」重新配置：每次连接设置 `busy_timeout` 并启用
WAL（WAL 让读与写可以并行，默认的回滚日志会互相阻塞），这是并发上的优化，
不是正确性的前提。

### 实测

```
两个进程，同一数据目录，各自监听一个端口：
  /api/ping 各自返回自己的 instance_id 与 pid，均无 is_primary
  /api/instances 列出两个实例
  杀掉其中一个：另一个继续服务，且仍在 `instances/` 里
  两侧并发各写 25 次设置：revision = 50（每次成功写入只推进一次），无 .tmp/.lock 残留
  两侧并发各写 20 条作品库记录：40 条都在，库可读
```

## 二、旧的单实例实现（已移除，保留说明）

命名互斥体、单一 `instance.json`、以及「第二个启动改为激活已有窗口」的整条路径都已删除。
`/api/activate` 仍然保留：它是「把某个窗口切到当前任务」的接口，只是不再由启动流程调用。

## 二、事件流：替代轮询，页面之间实时同步

新增 `GET /api/events`（Server-Sent Events）。`StateHub` 用一个版本号加条件变量：
写操作完成后 `bump()`，每个流线程 `wait(自己上次发送的版本)`，
所以**只在真的变化时推送**，而不是定时唤醒。

页面上 `EventSource` 是主通道，原来的轮询**保留为兜底**（流断了会重连，重连期间轮询照常工作）。

### 两个实现要点

1. **断开检测**：客户端关闭只能靠"写"发现。所以每个等待片（1 秒）都写一个 SSE 注释
   （`: keep-alive`），而不是每 15 秒才写一次。否则一个关掉的标签页会白占一个线程槽位
   15 秒。槽位总数封顶 12，超了返回 429 而不是无限开线程。
2. **渲染共用一条路径**：`applyStatus()` / `applyLease()` 同时被事件流和轮询调用，
   两条通道不可能渲染出不同的结果。

## 三、编辑租约：单写者

- 一个页面持有租约，其他页面**只读**；
- 租约 45 秒没心跳自动失效——**关掉的标签页不会把界面永久锁死**；
- 任何页面可以主动「接管编辑」；
- 非持有者的写操作返回 **409** 并说明当前持有者，不是 500 也不是静默失败。

### 一个刻意的边界

租约只对**自称身份**的客户端生效（页面用 `X-ComfyBatch-Client` 或请求体里的
`client_id`）。脚本或测试直接调 API 不带这个字段时不受限。

理由：租约是用来防止**两个界面互相覆盖**的，不是用来锁住自动化调用的。
把它做成对所有调用强制，只会让自动化莫名其妙地失败。

### 实测（两个真实标签页）

```
1. 页面 A 取得租约                 → granted=true, mine=true
2. 页面 B（经事件流得知，未轮询）   → readOnly=true
     横幅：「另一个页面正在编辑（p-40ywkfsoyvfu），本页为只读，
            避免两边保存不同配置互相覆盖。接管编辑」
     「启动批次」按钮 disabled=true
3. 页面 B 直接写 API                → HTTP 409
     「另一个页面正在编辑（页面标识 p-40ywkfsoyvfu）。为避免两边保存不同配置
       互相覆盖，这里已改为只读。要在这里编辑，请点「接管编辑」。」
4. 页面 B 点「实际检查」            → 提示而不再发那个注定失败的请求
     「本页为只读（另一个页面正在编辑）。要在这里操作请点顶部的「接管编辑」。」
5. 页面 B 点「接管编辑」            → readOnly=false，横幅变为「本页可编辑」
6. 接管后写入                       → HTTP 200, ok=true，任务标题更新
7. 页面 A 自动变为只读，横幅指向 B   → readOnly=true, holder=p-uugx4jbfyvxt
```

第 7 步是关键：角色互换后**另一个页面自动跟着变**，靠的是事件流，不是轮询。

### 只读页面是镜面，不是快照

只读页面会在每次推送时**采用服务端的任务列表**，所以编辑者的改动会实时出现在只读页面上。
编辑者自己的未保存编辑不受影响（不会被自己的服务端回包覆盖）。

## 四、测试

新增 `tests/test_live_sync.py`（29 项），覆盖：

- `StateHub`：版本推进唤醒等待者、无变化时超时、激活时间可观测；
- `EditLease`：首个持有者锁定、第二个页面被拒且被告知持有者、接管、重复取得、心跳续约、
  **过期后他人可接手**、非持有者不能释放别人的租约；
- `InstanceLock`：获取/释放往返、同名互斥体报告已存在；
- SSE 帧格式；**真实 socket 连接**验证连接即收到快照、外部变化会主动推送、
  断开后槽位被释放；
- 路由层：`/api/ping` 身份、两页租约仲裁、非持有者写被 409、接管后写入成功、
  无 `client_id` 的调用不被拦截、`/api/activate` 生效、`/api/status` 带租约；
- `instance.json` 往返，以及**陈旧/陌生文件不会被误认为目标实例**。
