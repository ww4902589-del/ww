# 前端重新规划：六阶段 + 常驻真相栏

本轮把单文件页面拆成三个文件，并按计划书的信息架构重排为六个阶段。重排本身不是重点，
重点是**重排过程中暴露并修掉了一类一直存在的缺陷**：页面上显示的值，未必是提交给
ComfyUI 的值。下面按"改了什么 → 为什么 → 怎么验证"记录。

当前版本：页面与服务端一致为 **V2.16**（`APP_VERSION`，测试 `test_server_and_page_versions_agree` 盯着）。

## 一、文件组织

```
src/
├─ index.html   结构（六阶段 + 真相栏 + 抽屉），一行一句，不放样式与脚本
├─ app.css      样式，按区块分段，一条声明一行
└─ app.js       脚本，按模块分段（状态与渲染入口 / 本地环境 / 导入与任务 / 工作流 /
                风格与 LoRA / 参数工作台 / 检查 / 运行 / 审图与确认 / 抽屉 / 租约与事件流）
```

服务端新增 `/app.css`、`/app.js` 两个静态路由，`/` 仍返回页面；打包 `S.spec` /
`ComfyBatch-V2.spec` 的 `datas` 同步增加。静态资源在启动时一次性读入内存
（`load_static_assets`），缺少任何一条会直接拒绝启动，所以打包漏文件不会变成"页面能开但没样式"。

## 二、六阶段

| 阶段 | 内容 |
|---|---|
| 1 文件与任务 | 本地环境（折叠，平时不展开）+ 提示词/图片导入 + 数量与正负面识别 + 任务范围分配 + 逐项方案 + Excel 映射入口 |
| 2 工作流 | 路径、**指纹**、可选分支、**实际分支**、采样与放大链路、输入输出能力 |
| 3 模型、风格与 LoRA | 中文名、文件名、强度、触发词、存在状态、实际写入位置 |
| 4 参数工作台 | 常用 10 + 高级 16，四种作用范围（独立阶段） |
| 5 检查与运行 | 最终生效工作流/分支/资源/采样阶段/放大链路/**预计输出尺寸**/阻断问题 + 启动/暂停/取消 |
| 6 成图预览与确认 | 结果看板、通过/打回重做/记录问题、键盘审图、原图查看器 |

阶段 2 与阶段 5 是本轮新增的事实面板：阶段 2 显示指纹与实际分支，阶段 5 显示采样阶段、
放大链路与预计输出尺寸（由基准尺寸 × 实际写入的放大倍数算出，不再只显示基准尺寸）。

## 三、常驻真相栏

右侧固定栏，不随阶段切换消失，内容全部来自现有接口：

```
工作流    ▶▷Krea2-极清生图流+SeedVR2-int8图像放大.json
指纹      5a8d78ddf157
分支      ①Krea2-二采出图2（save:6）
模型      redcraftHybridH3A2A_30Krea2.safetensors
尺寸      1280×720 → 1920×1080（×1.5）
参数      无覆盖
────────────────────────────
阻断      没有阻断问题
结果      尚无结果
进度      idle
```

**未检查时它不会假装知道。** 未跑检查前，工作流/分支/模型显示所选值并标注「（未检查）」，
指纹与尺寸显示「尚未检查」。`checked` 取自"是否真的跑过审计"（`audit.node_count`），
不是"用户选了什么"。

## 四、一个渲染入口

`state → render()`，事件流与轮询都只走这一条路径。`applyStatus` / `applyLease` /
`renderReview` 这些名字保留（测试断言它们存在），职责改为"写入状态并触发渲染"。

## 五、重排过程中暴露并修掉的缺陷

这一节是本轮最有价值的部分：五个缺陷都不是重排"引入"的，而是**重排之后才看得见**的。

### 5.1 换行落进 HTML 属性值（功能性）

旧的一次格式化把模板字面量文本当作代码来断行，`<select id="${sel}">` 变成
`id="<换行>  sel<换行>"`。HTML 属性值**原样保留空白**，于是 `getElementById("sel")`
再也匹配不上，`select.value` 也不再等于预期字符串——正好落在"软件内替换模型"这条链路上。

同时它把 `body:'{}'` 断成 `body:'{<换行>}'`：单引号字符串里不能有裸换行，整段脚本
因此静默死掉（页面能看、点了没反应）。**原来的守卫看不见这两类**：它比较"去掉所有空白后的
内容"，而 `'{<换行>}'` 与 `'{}'` 去掉空白后完全相同。

### 5.2 词法器分不清"模板文本"和"插值内部"

根因是只有一份扫描器、写在格式化器内部，遇到第一个 `${` 就把 `in_template` 置为
`False` 且从不复位，之后所有引号都被当成代码读——这正是 5.1 的来源。

本轮把它收敛成**项目唯一的词法器** `tools/js_lexer.py`：模板文本（`TEMPLATE`）与
`${...}` 内部（`EXPR`）分开标记，正则字面量单独处理。三个地方共用它，不再各写一份：

- `tools/js_lexer.py` 扫描与修复；
- `tools/reformat_frontend.py` 断行与缩进；
- `tests/test_script_parses.py` 的两条守卫（字符串跨行、属性值内换行）。

为什么强调"唯一"：本轮先后有两份自写的扫描器都报"0 处问题"而实际有 14 处和 80 处。
第一份把 `<` / `"` 在**代码**里的出现也算进标签状态（状态被污染）；第二份漏了正则字面量
（正则里的引号被当成字符串起点，之后整体错位）。同一个判断存在两份实现，就会有一份是错的。

### 5.3 左侧导航压在内容上（点不到按钮）

新版网格只给 `.content`（第 2 列）和 `.truth-rail`（第 3 列）写了显式列位置，`step-nav`
留给自动放置，结果它与内容**同占第 2 列**。导航是 `position: sticky` 定位元素，绘制在
内容之上，于是那块深色导航盖住了「检查实际生效配置」按钮——真实鼠标点击落在
`BUTTON.step-tab` 上，按钮永远点不到。

修法是三个子元素都显式指定列与行，并让两个媒体查询跟着重置；同时删掉了被取代的旧
`.workspace` 规则（两套布局规则并存，也是同一类"两份实现"的隐患）。

### 5.4 抽屉用 `hidden` 属性，却被 CSS 的 `display:flex` 顶掉

`#drawer` 带 `hidden` 属性，但 `.drawer { display:flex }` 覆盖了浏览器默认的
`[hidden]{display:none}`。于是抽屉**就算"关着"也依然**以 `position:fixed; right:0;
width:560px; z-index:60`、`opacity:1`、`pointer-events:auto` 的姿态压在真相栏上，
真相栏里「阻断问题」那个按钮同样点不到。

修法是补一条 `.drawer[hidden]{display:none}`，并加一条会真正失败的守卫
（`tests/test_page_assets.py::HiddenToggleTests`）：凡是用 `hidden` 属性切换、又有 author
`display` 规则的元素，必须有对应的 `[hidden]` 覆盖。守卫带负向控制、后代选择器与
"类名恰好叫 hidden"三种反例，避免它自己变成误报源。

### 5.5 真相栏与"实际生效检查"互相矛盾

两处：

1. **阻断时真相栏说"没有阻断问题"。** 前三层预检（结构/资源/参数）在**编译之前**就拒绝，
   没有审计数据；而真相栏的阻断计数只读审计的 `blocking`，于是同一屏上左边写「不能生成」、
   右边写「没有阻断问题」。现在服务端给出唯一的 `blocking_count`（= 审计阻断 + 预检错误），
   预检错误同时在抽屉顶部列出原因。
2. **预检后真相栏不刷新。** 阻断返回 HTTP 400，走的是 `catch` 分支；`catch` 只更新了
   「实际生效检查」面板，没写 `lastInspect`、没重画真相栏。现在两条路径都写、都画，抽屉
   开着时也跟着刷新（避免旧内容一直挂着「预检 未通过」）。

另外 `prepare_config` 原本在 `try` 之外，它失败时连结构化上下文都没有，页面拿不到任何原因。
现在它也在 `try` 内，且 `blocked_preflight_payload()` 保证"阻断必带原因"。

### 5.6 同名不同义的「工作流指纹」

`capabilities()` 发布的 `workflow.fingerprint` 是**文件字节的 sha256**，而审计、资源替换规则、
参数默认值用的都是**结构指纹**。同一屏上于是出现两个「工作流指纹」——生效面板 `8fd031e27fd8`，
真相栏 `5a8d78ddf157`。结构指纹是设计里唯一的那个（只拖动节点不该让已确认的替换规则失效），
现在报告里发布的是它，字节哈希改名为 `file_hash` 单独保留。

## 六、可读性工具链

`tools/reformat_frontend.py` 把脚本断成一行一句，只在这三处断行：代码里的 `{`/`}`/`;`
（括号闭合时），以及模板字面量里 `>` 与 `<` 之间（标签之间插入换行不产生文本节点，
渲染完全等价，且不可能落进属性值）。它自带三道闸门，任一不过就拒绝写盘：

1. 去空白后内容必须完全一致；
2. 输出里不允许出现"落在属性值内的换行"（去空白比较看不见这一类）；
3. 再跑一次必须完全不变（幂等）。

效果：`app.js` 最长行从压缩形态的 2793 字符降到 **750**，`app.js` 1816 行、`app.css` 1050 行。

`tools/js_lexer.py --fix` 用于修复历史文件里已经落进属性值的换行；
日常只需 `python tools/js_lexer.py app.js` 复核，应当报"属性值内 0 处"。

## 七、本轮不做

- 不改视觉风格（保持暖色纸质感），只重排布局与层次；
- 不改后端业务接口，只新增两个静态路由与 `blocking_count` / `preflight_errors` / `inspected` 字段；
- 不做移动端适配（窄窗只保证真相栏落到内容下方，不被挤没）。

## 八、怎么复核

1. `python -m unittest discover -s tests` —— 320 项，其中
   `test_script_parses`（字符串跨行、属性值内换行）、`test_page_assets::HiddenToggleTests`、
   `InspectPayloadTests`（阻断必带原因）是本轮新增的守卫。
2. `python tools/js_lexer.py app.js` —— 应报"属性值内 0 处"。
3. `python tools/reformat_frontend.py` —— 应报 "whitespace only, stable"，不写盘。
4. 起服务后在浏览器里走一遍：选工作流 → 「实际检查」→ 看真相栏的指纹/分支/尺寸是否与
   「实际生效检查」面板一致。
