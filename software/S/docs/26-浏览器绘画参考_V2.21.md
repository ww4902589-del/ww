# 浏览器绘画参考与 `reference` 接入（任务 #13）

## 现场与边界

- 本任务在桌面任务清单独占领取，分支 `handoff/local-s-reference` 基于 `7adaa6e`；起始工作树与 `origin/main` 无差异。
- 当前浏览器可导入 PNG/JPEG/WEBP 图片。`/api/import-images` 验证文件后写入本机 ComfyUI `input/ComfyBatch-V2/imports/<session>`，生成图片任务的 `metadata.source_image`。
- 工作流适配器将 `source_image` 写入已识别的 `LoadImage` 输入；预检以实际工作流是否具备图片输入节点为准。
- 当前任务模型和工作流没有独立的 `reference` 字段或节点映射。不能把画布数据仅存浏览器而宣称已接入生成。
- #9 负责通用工作流识别与映射；本任务不扩展任意节点映射。#2/#3/#5/#6/#7/#8/#11/#12 的生成和审图逻辑保持边界。

## 输入与验收草案

1. 在浏览器画布用鼠标或触控笔绘制，能清空、预览并导出标准 PNG。透明区域的处理需确定，避免把空白图误当有效参考。
2. 绘图仅留在本机浏览器与本机服务；服务端仍执行格式、大小和图像有效性检查，不信任文件名或浏览器提供的 MIME。
3. 保存或应用后，用户能在任务列表看到参考图和对应任务，刷新状态后仍能追溯；未选择任务、空画布、无图片输入节点和导入失败均给出明确反馈。
4. 实际生成必须使用该图；行为测试检查提交给 ComfyUI 的图节点路径、任务归属与审计信息，不以界面预览替代证明。
5. 真机生图验收如需输入素材，使用桌面 `01.docx`（word01）提供的材料。

## 已确定的接入方式

用户已确认：`reference` 接入现有图片输入。画布导出的 PNG 作为一个图片任务提交给 `/api/import-images`，由现有服务端验证并生成 `metadata.source_image`，由已识别的 `LoadImage` 接收。界面将它称为「绘画参考」，但不引入独立的工作流节点映射或静默覆盖其它任务的图片。后续实现与测试需证明端到端路径及无图片输入节点时的预检反馈。
